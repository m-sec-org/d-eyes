# D-Eyes 技术规划方案

## 1. 项目概述

D-Eyes是一款综合性安全检测与响应工具，由M-SEC社区驱动，提供面向安全响应、合规审计、资产梳理以及供应链安全的多场景能力。本技术规划方案旨在指导D-Eyes项目的未来架构演进、功能扩展和技术升级，构建更强大、更灵活的安全检测平台。

> 代码结构更新：自当前迭代起，原有命令行实现已归档至 `agent/` 子目录作为 D-Eyes Agent，新建的 D-Eyes Server 项目位于 `server/`，按照下文规划逐步实现分布式架构。

## 2. 架构设计

### 2.1 整体架构演进

**现状分析**：当前D-Eyes采用单体命令行工具架构，各功能模块相对独立但缺乏集中管理能力。

**目标架构**：实现Agent-Server分布式架构，支持集中化管理与分布式执行，提升在大规模环境下的可用性和管理效率。

**架构图**：
```
+-------------------+    +-------------------+
|   管理控制台      |    |   RESTful API     |
|   (Web UI)        |<-->|   服务层          |
+-------------------+    +--------+----------+
                                   |
                        +----------v----------+
                        |   核心服务层        |
                        |   (Server Core)    |
                        +----------+----------+
                                   |
          +------------------------+------------------------+
          |                        |                        |
+---------v---------+    +---------v---------+    +---------v---------+
|    任务调度服务    |    |    数据管理服务    |    |    Agent管理服务  |
+---------+---------+    +---------+---------+    +---------+---------+
          |                        |                        |
          +------------------------+------------------------+
                                   |
                    +-------------v-------------+
                    |                           |
          +---------v---------+    +------------v----------+
          |   插件管理系统    |    |    认证授权系统       |
          +-------------------+    +-----------------------+

                                   |
                    +-------------v-------------+
                    |                           |
          +---------v---------+    +------------v----------+
          |   Agent节点      |    |    Agent节点         |
          |   (Linux)        |    |    (Windows)         |
          +-------------------+    +-----------------------+
```

### 2.2 组件设计

#### 2.2.1 Server端组件

1. **核心服务层**
   - **任务调度服务**：负责任务的创建、分发和状态管理
   - **数据管理服务**：负责检测数据的存储、索引和检索
   - **Agent管理服务**：负责Agent的注册、认证和生命周期管理
   - **报告生成服务**：负责检测报告的生成和格式化

2. **API层**
   - **RESTful API**：提供标准的HTTP接口，支持第三方系统集成
   - **gRPC API**：为Agent提供高效的通信接口
   - **WebSocket API**：支持实时事件推送

3. **前端组件**
   - **管理控制台**：基于React/Vue的Web界面，提供可视化管理能力
   - **数据可视化**：支持检测数据的图表化展示
   - **任务配置器**：提供图形化的任务配置界面

4. **基础设施层**
   - **存储系统**：支持MySQL/PostgreSQL存储结构化数据，Elasticsearch存储日志和事件
   - **消息队列**：基于Kafka/RabbitMQ实现组件间通信
   - **缓存系统**：使用Redis提升系统性能
   - **配置中心**：集中管理系统配置

#### 2.2.2 Agent端组件

1. **核心组件**
   - **通信模块**：负责与Server端的通信，支持gRPC和HTTP协议
   - **任务执行器**：负责接收和执行来自Server端的任务
   - **数据采集器**：负责收集系统信息和检测数据
   - **本地缓存**：支持离线工作模式，存储任务和结果
   - **安全控制模块**：负责BAS模拟过程中的安全边界控制和风险缓解

2. **功能模块**
   - **应急响应模块**：恶意文件检测、进程分析、网络连接检查等
   - **基线检查模块**：系统配置检查、安全基线评估等
   - **资产探测模块**：主机发现、端口扫描、服务识别等
   - **供应链分析模块**：SBOM生成、依赖分析等
   - **入侵和攻击模拟(BAS)模块**：攻击链模拟、漏洞验证、权限提升测试等

3. **插件系统**
   - **插件管理器**：负责插件的加载、卸载和版本管理
   - **插件接口**：提供统一的插件开发接口
   - **插件仓库**：管理可用插件的仓库

## 3. 功能规划

## 5. 实现路径

### 5.1 阶段一：基础架构搭建（3个月）

**目标**：构建Agent-Server基础架构，实现核心通信和管理功能。

**关键任务**：
1. 设计并实现Server端核心服务层
2. 开发Agent端基础框架和通信模块
3. 实现Agent注册、认证和任务分发机制
4. 搭建基础存储系统和消息队列
5. 开发简单的Web管理界面原型

**里程碑**：
- Agent能够成功注册到Server并接收简单任务
- Server能够管理Agent状态和基本信息
- 基础Web界面可展示Agent列表和状态

### 5.2 阶段二：核心功能迁移（4个月）

**目标**：将现有功能模块从单体架构迁移到分布式架构。

**关键任务**：
1. 将应急响应模块迁移到Agent端
2. 将基线检查模块迁移到Agent端
3. 将资产探测模块迁移到Agent端
4. 将供应链分析模块迁移到Agent端
5. 实现入侵和攻击模拟(BAS)模块的基础架构
6. 在Server端实现任务调度和结果聚合
7. 完善Web管理界面的任务配置和监控功能

**里程碑**：
- 所有现有功能模块可在分布式架构下运行
- Server可统一调度和管理Agent执行任务
- BAS模块基础架构完成，支持简单的攻击模拟
- 支持任务结果的集中查看和报告生成

### 5.3 阶段三：高级功能实现（5个月）

**目标**：实现高级功能，提升系统的安全分析和自动化能力。

**关键任务**：
1. 开发威胁情报集成模块
2. 实现异常行为检测和关联分析
3. 开发自动化响应系统和Playbook功能
4. 实现合规管理和多框架支持
5. 开发高级数据可视化和报表功能
6. 优化系统性能和扩展性
7. 完善BAS模块，实现完整攻击链模拟和安全控制
8. 开发BAS场景管理和编排功能

**里程碑**：
- 系统能够进行高级安全分析和自动响应
- 支持多种合规框架的检查和报告
- BAS模块支持完整的攻击链模拟和安全验证
- 具备良好的性能和扩展性，可支持大规模部署

### 5.4 阶段四：完善和优化（3个月）

**目标**：完善系统功能，优化用户体验，确保系统稳定可靠。

**关键任务**：
1. 完善插件系统，支持第三方扩展
2. 优化Agent端的资源使用和扫描效率
3. 增强系统的安全性和可靠性
4. 完善文档和用户指南
5. 进行全面的测试和性能优化
6. 开发运维工具和监控系统

**里程碑**：
- 系统功能完善，性能稳定
- 提供完整的文档和用户支持
- 具备生产环境部署和运维能力

## 6. 扩展性规划

### 6.1 插件体系

**设计原则**：
- 采用松耦合的插件架构，支持动态加载和卸载
- 提供统一的插件接口和开发框架
- 实现插件的版本管理和依赖控制
- 支持插件的沙箱隔离，确保系统安全

**插件类型**：
- 检测插件：提供特定类型的安全检测能力
- 响应插件：实现特定的安全响应动作
- 数据源插件：接入外部数据源
- 报告插件：生成特定格式的报告
- BAS攻击插件：实现特定类型的攻击模拟技术
- BAS场景插件：定义和编排完整的攻击场景

### 6.2 API扩展

**RESTful API**：
- 提供完整的资源管理API
- 支持版本控制和向后兼容
- 提供API文档和SDK

**Webhook支持**：
- 支持事件触发的Webhook通知
- 可配置的事件类型和过滤规则
- 支持重试机制和故障处理

**第三方集成**：
- SIEM系统集成
- 工单系统集成
- 企业消息系统集成
- DevOps工具链集成

### 6.3 部署模式

**单机部署**：
- 适合小型环境和测试使用
- 所有组件运行在单一主机上

**集群部署**：
- 适合中大型环境
- 支持水平扩展
- 提供高可用性保证

**混合部署**：
- 支持私有云和公共云混合部署
- 支持跨区域部署和数据同步
- 提供边缘计算支持

- 支持多因素认证

- 数据脱敏和匿名化
- 数据备份和恢复机制
- 数据保留策略和合规删除

### 7.4 Agent安全

- Agent代码签名和验证
- 运行时完整性保护
- 最小权限原则
- 异常行为监控和自保护

- 模拟行为影响范围限制
- 危险操作沙箱隔离
- 操作审计和可追溯性

## 9. 风险评估

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 架构复杂性增加 | 开发和维护难度增加 | 分阶段实施，完善文档和测试 |
| 系统性能挑战 | 大规模部署时性能下降 | 性能优化，分布式架构设计 |
| 兼容性问题 | 不同环境下的兼容性问题 | 广泛的测试覆盖，提供详细的兼容性指南 |
| 安全性风险 | 新增组件可能引入安全漏洞 | 安全编码实践，定期安全审计 |
| BAS操作风险 | 攻击模拟可能导致实际损害 | 严格的安全控制，操作前确认机制，沙箱隔离 |
| 环境差异性 | 不同环境中BAS效果差异大 | 环境适应性设计，提供详细的使用指导和限制说明

### 9.2 项目风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 进度延迟 | 项目交付延期 | 详细的项目计划，合理的资源分配，定期进度跟踪 |
| 资源不足 | 影响项目质量和进度 | 提前规划资源需求，考虑外部合作 |
| 需求变更 | 范围蔓延，进度延误 | 严格的需求管理流程，变更评估和控制 |
| 社区参与度 | 开源贡献不足 | 完善贡献指南，活跃社区交流，举办开发者活动 |

## 10. 结论

本技术规划方案为D-Eyes项目提供了从单体命令行工具向分布式Agent-Server架构演进的路线图。通过分阶段实施，将逐步构建一个功能更强大、架构更灵活、扩展性更好的安全检测平台。该方案注重技术先进性与实用性的平衡，同时考虑了项目的可执行性和风险控制，为D-Eyes项目的长期发展奠定了坚实基础。
