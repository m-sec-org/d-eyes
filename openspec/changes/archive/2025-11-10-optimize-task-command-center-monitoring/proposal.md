# Proposal: Optimize Task Command Center Real-Time Feed

## Why
实时监控列表以秒级频率追加新数据，DOM 无限增长导致：
- 页面高度快速膨胀，阻挡下方关键指挥信息
- 浏览器重排频繁，滚动与交互明显卡顿
- 用户无法冻结视图或筛选重点事件，错过关键信息

## What Changes
- 引入虚拟滚动与批量渲染策略，仅保留最近 N 条（可配置）事件在 DOM 中，其余折叠至时间分段中
- 添加“冻结/恢复”与“按时间窗口筛选”控件，保证用户在分析时不会被流量顶走
- 固定顶部关键指标（告警计数、任务状态分布）与操作区，不再随列表增长移动
- 定义前端对高频推送的节流与批次合并规则，确保 60 FPS 内保持 < 16ms 渲染预算

## Impact
- 需要调整 align-ops-console 规格，补充 Task Command Center Feed 的 UX 与性能约束
- 实现侧需评估现有 WebSocket 事件模型与前端状态管理（可能引入数据窗口存储）
- 需新增性能回归指标（事件吞吐、渲染耗时）用于验收
