# 0.2 对齐口径收敛（Decisions）

> change-id: `align-frontend-server-core-capabilities`  
> 本文用于把 0.2 阶段需要“收敛成硬口径”的内容写清楚，作为后续 1.x（Specs）与 2.x/3.x（实现）的一致输入。

## 1) `required_capabilities` 默认策略（Frontend + Server）

### 1.1 语义（不变更既有合同）

- `required_capabilities` 存放于 task `metadata.required_capabilities`，类型为 **string**，支持 **逗号分隔**（Server 调度器支持 `,`/`;` 分隔并会 trim 空白）。
- 调度语义：`required_capabilities` 非空时，Scheduler **仅**会把任务 lease 给 capabilities 集合满足该列表的 Agent。

### 1.2 Frontend 注入规则（建议口径）

- **WHEN** Ops Console 通过表单创建任务  
  **THEN** 默认注入 `metadata.required_capabilities`，以减少误调度与失败噪声。
- 取值优先级：
  1. `GET /api/v1/task-types` 返回的 `task_type.capabilities[]`（**按原顺序**用 `,` 连接）
  2. 兜底：`<task.type>`
- 输出规范：使用小写能力名；连接符固定为 `,`；不输出空元素（例如 `",,"`）。

### 1.3 Server 兜底规则（回归兼容）

- **WHEN** 客户端未提供 `metadata.required_capabilities` 且 task type 可在 catalog 中解析到非空 `capabilities[]`  
  **THEN** Server 在持久化时注入默认值（逗号分隔）。
- **AND** Server 不覆写显式传入值；未知 task type 不强制注入。

## 2) `detect.memscan` 审批字段与 UI guardrails

### 2.1 基础约束（guardrails）

- `payload.pid` 与 `payload.all` 必须二选一（与 catalog profile constraint：`xor(pid, all)` 对齐）。
- `payload.pid` 必须为 `>= 1` 的整数；选择 `payload.all=true` 时应清空/省略 `pid`。

### 2.2 审批 metadata（必须为字符串）

memscan 远程执行会由 Agent 侧校验审批字段（缺失将被拒绝），因此 UI 必须在创建前完成“显式确认”并写入 metadata：

- 必需：
  - `memscan_approval_required="true"`
  - `memscan_approved="true"`
- **WHEN** `payload.evidence=true` 或 `payload.minidump=true`  
  **THEN** 额外必需：
  - `memscan_evidence_approved="true"`

说明：
- Agent 侧对 `"true"` 采用大小写不敏感判断，但 UI 侧推荐统一输出小写 `true`，避免口径漂移。

### 2.3 Windows-only + opt-in 提示口径

- `detect.memscan` 为 Windows-only 能力；UI 必须提示需要 Windows Agent。
- 该能力为高敏操作，且需要 Agent 侧显式 opt-in（`allow_memscan="true"`）；UI 必须提示运维需要通过 Agent 配置/部署来启用，而不是依赖在控制台编辑 labels。

## 3) audit/detect report/read 展示字段与错误提示口径

### 3.1 读取面（稳定契约）

- audit：`GET /api/v1/tasks/{id}/audit/report`
- detect：`GET /api/v1/tasks/{id}/detect/report`

UI 以 report endpoint 作为稳定读取面（相比 `task.last_run.summary` 更契约化），用于详情页/报告页展示与排障提示。

### 3.2 展示字段（最小稳定子集）

建议 UI 至少展示：

- 元信息：`task_id`、`task_type`、`profile`、`run_id`、`agent_id`、`task_status`、`completed_at`
- 执行摘要：`result.summary.command`、`result.summary.status`、`result.summary.duration_seconds`、`result.summary.risks`、`result.summary.notes`
- 产物列表：`result.summary.outputs[]`、`result.artifacts[]`
  - 当前多为 Agent 本地路径；UI 不提供“下载”，仅提供复制路径/说明（集中回收属于 Non-Goals）。
- 排障字段：`exit_code`、`error_code`、`result.error`

### 3.3 错误提示（可操作口径）

- HTTP 403：提示无 `reports.view` 权限（并建议联系管理员/切换角色）。
- HTTP 404 且 message 指向 summary 不可用：提示任务尚未产出报告（可提示稍后重试/查看 last_run）。
- memscan 审批缺失：
  - `error_code=detect.memscan.approval_required`：提示补齐 `memscan_approval_required/memscan_approved`
  - `error_code=detect.memscan.evidence_approval_required`：提示补齐 `memscan_evidence_approved` 或关闭 evidence/minidump
